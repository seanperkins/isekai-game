# Isekai Chronicles

A side-scrolling platformer built in Godot where you die, reincarnate as a monster, and evolve each new body through what it eats and learns. It is a fixed, hand-built metroidvania world: death starts a new life in the same world, and what you unlock between lives opens routes that were closed before.

Inspirations: *That Time I Got Reincarnated as a Slime*, *So I'm a Spider, So What?*, Hollow Knight (the hand-built world) and Dead Cells (permanent unlocks between lives).

> Status: a playable prototype. The slime is the playable form; the wolf, goblin and spider movesets exist in a sandbox and are not yet wired into the real player.

## The game

- **Opening.** A truck kills you in a rigged JRPG battle (every command fails, with a few jokes on the trope), then a goddess apologizes and reincarnates you as a slime. It plays once on a new profile.
- **Every enemy is a potential you.** Each creature is both a foe and a playable form. Eating or beating enough of one makes it a species you can reincarnate as.
- **Essence and evolution.** Essence is elemental (water, earth, air, light, dark). Eating creatures fills it, powers evolve by spending it, and the mix you hold decides which evolutions are offered.
- **Skills level up through use.** Some unlock by essence, others by doing something (eat a spider N times, dodge N times).
- **Souls and altars.** Altars (one per area) let you attune a respawn point, bank essence into soul points, and meet the goddess, who offers your next body. Soul points buy species and permanent perks.
- **Four areas:** Cave, Grotto, Flooded Tunnels and the Deep, with boss arenas.

The design is written up in [`docs/isekai-chronicles-design-doc.md`](docs/isekai-chronicles-design-doc.md). Two visual guides are published online: [area design](https://seanperkins.github.io/isekai-game/guides/area-design.html) and [species evolution](https://seanperkins.github.io/isekai-game/guides/species-evolution.html) (all guides: [index](https://seanperkins.github.io/isekai-game/guides/)).

## Run it

You need [Godot 4.7](https://godotengine.org/) with `godot` on your `PATH`.

```sh
godot --path .                                         # play
godot --path . -- --opening                            # replay the opening
godot --path . -- --skip-opening                       # skip it
godot --path . -- --evolve                             # start at the first body evolution
godot --path . res://scenes/movement_sandbox.tscn      # the species movement sandbox
tools/edit_rooms.sh                                    # the room editor
```

Or open the folder in the Godot editor and press F5. The window is 640x360 scaled to 1280x720.

### Controls

| | Keyboard and mouse | Gamepad |
| --- | --- | --- |
| Move | A / D | Left stick, D-pad |
| Aim | W / S, or the mouse cursor | Left or right stick, D-pad |
| Jump | Space | A |
| Tackle | J (or Shift with the mouse) | X |
| Eat (hold) | K (or F) | B |
| Inspect | I (or R) | Y |
| Skills | U / O / H / L (or LMB, RMB, Q, E) | LB, RB, LT, RT |
| Skill screen | Esc | Start |
| Input debug | F3 | Back |
| Fullscreen | F11 | |

## Tests

The suite uses [GUT](https://github.com/bitwes/Gut) (vendored in `addons/gut`) and runs headless:

```sh
tools/run_tests.sh              # everything
tools/run_tests.sh altar        # only test files whose name contains "altar"
```

Godot's exit code is not trusted: the script reads the log and the JUnit XML and fails on any engine error, an empty run or a failed test. See `tools/run_tests.sh` for `FIXED_FPS` and `TEST_TIMEOUT`.

Manual checks live in [`docs/playtest-checklist.md`](docs/playtest-checklist.md).

## Project layout

| Path | What is in it |
| --- | --- |
| `scripts/` | Game code by system: `player`, `movement`, `abilities`, `enemies`, `soul`, `world`, `ui`, `audio`, `editor` and more |
| `autoload/` | Singletons: `Controls`, `EventBus`, `SkillRules`, `Compendium`, `Announcer`, `Audio` |
| `scenes/` | `main.tscn`, the room editor, the movement sandbox |
| `data/` | Authored content as Godot resources: rooms, creatures, forms, skills, species, movement profiles, soul rules, the opening |
| `assets/` | Built art and audio (committed) |
| `art_source/` | Source frames for the art pipeline (the large raw outputs are git-ignored and regenerable) |
| `tests/` | The GUT suite, one `test_*.gd` per feature |
| `tools/` | Test runner, room editor, content builders, screenshot scripts, the art and audio pipelines, Pages publishing |
| `docs/` | Design doc, specs and plans, execution ledgers, research, the bestiary and design-review pages |

### Content is data

Rooms are edited in the room editor and saved to `data/rooms/*.tres`; there is no world generator. Creatures, forms, skills and species are `.tres` resources too, and some are generated by `tools/build_*.gd` scripts, so re-run the builder rather than hand-editing its output (the opening's copy is in `tools/build_opening.gd`). Details in [`docs/rooms.md`](docs/rooms.md).

### Art and audio

Sprites and backdrops are generated with an image pipeline (`tools/art/`, frame specs in `*_frames.json`) and assembled into sheets; sound effects and music beds are synthesized (`tools/audio/`). Both have Python tests alongside them. The built outputs in `assets/` are committed, so you do not need to run the pipelines to play.

### Docs

- `docs/superpowers/specs/` and `plans/` — dated design specs and implementation plans per feature
- `docs/ledgers/` — one execution ledger per feature: the decisions taken, deferred findings and test results ([index](docs/ledgers/README.md))
- `docs/research/` — reference notes on movement, level design, damage formulas and species evolution; the [published guides](https://seanperkins.github.io/isekai-game/guides/) are built from its `*-report.html` files
- `docs/bestiary/` and `docs/design-review/` — static pages; `tools/publish_pages.sh` publishes them (plus the visual guides) to GitHub Pages. The live site lags `main` on purpose and only updates when you run that script.

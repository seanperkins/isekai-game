# Room Editor, Phase 3 — Design

Status: revised after round 1 of the debate (2026-10-01). Phase 3 of `docs/superpowers/specs/2026-09-29-room-editor-design.md`,
after P2 (`2026-09-30-room-editor-p2-design.md`, shipped). Sean's queue is: finish the editor, then add biomes and enemies from
*So I'm a Spider, So What?* and *That Time I Got Reincarnated as a Slime*. The art for two new biomes (`deep`, `flooded`:
terrain, back walls, parallax layers, decor sprites) is already in `assets/`, but no room uses them and the editor cannot make
one: its area list is the constant `["cave", "grotto"]` and it has no way to place decor. Round 1 found that the first draft was
two phases in one (what authoring a new-biome room needs, and general editor ergonomics) and that the second half carried the
riskiest bookkeeping (file deletion, a three-room undo, a kit panel). P3 is now the first half plus the cheap ergonomics that
authoring needs; the rest is P4 (Ruling 2). Research: `docs/research/level-design-reference.md`.

## What I understood

After P2 Sean can build a room's solids, creatures, exits, features and kits without a text editor. He cannot yet: choose a
room's biome from what the art supports; place the decor that makes a room read as its biome (crystals, fungus, hanging roots,
stalactites); resize a ledge by dragging its edge or fix it to an exact number; turn a thin ledge into one you cannot jump up
through; copy a ledge or a creature from another room; pick the right one of two overlapping things; set an exit's `gate` or a
tablet's `hint`; or see the jump budget he is building to.

**Success for P3:** author a complete room in a *new biome* without a text editor: pick `deep` or `flooded`, draw it, resize
and place its ledges exactly, dress it with that biome's decor (standing and hanging), copy a ledge or a creature from another
room, set its exits' gates and a tablet's hint, and see the base jump's reach while building. "Validate clean" stays the same
thing as "the suite's rule tests would pass", for decor and for gates as well.

## The phases

| Phase | What it delivers |
|---|---|
| P1 (shipped) | Separate editor scene; Solids, creatures, paired exits, New room beside, undo, Validate, save, Play from here |
| P2 (shipped) | `RoomLint`, the live problems list, features (pool, tablet, switch, rebirth pool), the inspector (exit shortcut, tablet text, switch, pool kit), Grow, two Play toggles, the World view |
| **P3 (this spec)** | Biomes from data and a Room panel (area, clear dressing); selection cycling; solid numeric fields and the hard-ledge toggle; resize handles; the Decor tool; copy and paste; exit `gate` and tablet `hint`; a jump ruler |
| P4 (later spec) | The Start tool and moving the world's start with its default pool; shrinking and deleting rooms; a free-form Play kit; pool affinity (with its eligibility rule moved into lint); numeric fields for creatures, features, decor and exits; cut and duplicate; a collision-only view; a JSON lint export for CI; physical reachability, assumed abilities and gate enforcement; prefab stamps and room templates; moving a room on the World view; dressing; autosave |

## Decisions (P3)

| Area | Decision |
|---|---|
| Biomes | The area list comes from data, not a constant: `TerrainArt.biomes() -> Array` returns the sorted directory names under `res://assets/tiles/` that `has_biome` accepts (today `cave`, `deep`, `flooded`, `grotto`). New Room's Area control (`EditorPanels.AREAS`) and the Room panel read it; adding a biome's art makes it appear with no code change. The World view colours a room by its area: explicit colours for the four known biomes and, for any other area, a colour derived from the area name's hash, so a new biome is never drawn in grey. A room whose `area` has no terrain art is not refused (the game falls back to flat tiles). |
| The Room panel | The right-hand slot, when **nothing is selected** and no problems list is open, shows the room panel: id and size (read-only), an **Area** dropdown (`TerrainArt.biomes()`) and, only when the room has `dressing`, a **Clear dressing (N)** button. Changing the area is one undo step: it sets `area` and sets the `area` of every `rebirth_pool` in the room to the new value (a pool's area is its room's, as `add_feature` stamps it); it touches nothing else. Dressing is not drawn in play (Ruling 1) and no biome-less library can hold it, so a room moved to `deep` or `flooded` gets the validator's existing `dressing needs a piece library` error until the author presses **Clear dressing**, which empties `dressing` in one undo step. Delete room and Shrink are P4. |
| Selection kinds | One new kind beside `solid`, `spawn`, `exit`, `feature`: **`decor`**. `hit` priority: spawn, feature, decor, exit, solid. Every kind has an explicit arm in `hit`, `begin_move`, `move_to`, `delete_selection`, the outline and the inspector, and each `_` arm refuses (the rule P2 set). The inspector (slot) now has a panel for a **solid** (numeric fields, see below), for an exit and for a feature as in P2; a **creature** and a **decor** piece select without a panel (the slot shows the room panel, as for nothing selected), because nothing about them is editable by number in P3. |
| Selection cycling | The model gains `hit_all(room_id, p, pick) -> Array` (every element under the point, in the priority order above, nearest spawn first, smaller solids first); `hit` is its first element. At **press** the view computes the candidates; if the current selection is among them it **keeps** it and begins the move on it (so a cycled-to element can be dragged), else it selects the first candidate. At **release**, if the pointer travelled **less than 3 screen pixels** since the press (a click, decided by pointer travel, not by the model's `serial`, which does not advance for a drag that ends where it began, a drag under half a grid step, or a creature dragged through rock), the press began on an element that was already selected and there is more than one candidate, the selection moves to the next candidate (wrapping). Anything else behaves as in P2. |
| Solid numeric fields | A selected solid gets a panel with `x`, `y`, `w`, `h` and **Rock from below** (below). Each number is a `SpinBox` (whole pixels, `min_value` / `max_value` from the room: `x` 0..width-`MIN_SOLID`, `y` 0..height-`MIN_SOLID`, `w` `MIN_SOLID`..width, `h` `MIN_SOLID`..height, so the control clamps what it cannot hold) that commits on `value_changed` (Enter, an arrow or focus loss; `_commit_pending` releases focus first, so the P2 rule covers it). The model keys are `get_field` / `set_field` `x`, `y`, `w`, `h`, `hard`. A set builds the new rect exactly (**not snapped**: typed numbers exist for what the grid cannot express, such as C1's ledge at y 266) and refuses, changing nothing, when the rect is not wholly inside the room or **is identical to another solid in the room** (Ruling 6); the control then shows the stored value again and the reason goes to the status bar. A refused combination is a model refusal; a number outside one control's own range is simply clamped by the control. |
| Hard ledges | A solid that is thin (`size.y <= 24` and `size.x > 24`: `RoomBuilder.is_one_way` without the mark) has a **Rock from below** checkbox, the `hard` field: it adds or removes the rect in `hard_ledges` (`set_field(hard, true)` on a thick solid is refused). A solid that stops being thin (resized or typed) **loses its mark in the same step**, because a thick solid is rock anyway and the validator rejects a mark on one. The Solid tool's live label reads the mark. |
| Stale numbers | The inspector is still rebuilt only when the selection changes. In addition `InspectorPanel.refresh()` re-reads every control from `get_field` and is called on every `_sync` while the same selection is open, **skipping a control that has keyboard focus** (a `SpinBox`'s inner `LineEdit` included). Without it a number typed before a drag would still show the old value and a focus-out would commit it, moving the element back. |
| Resize | A selected solid draws eight handles (four corners, four edge midpoints) as small squares of `HANDLE_PX` = 6 screen px. A press picks the **nearest** handle within `r = min(HANDLE_PX, 0.35 x the smaller on-screen side of the solid)`; a press inside the rect and farther than `r` from every handle moves the solid, as in P2 (so a 12 px ledge at the fit zoom of a 1x1 room (0.7375, 8.85 screen px tall: r = 3.1 px) still moves from its middle and on a 6x6 room at zoom 0.1229, where r falls below a screen pixel for any ledge, a ledge moves from anywhere but within r of a handle). Dragging a handle moves the edge or edges on its side in 4 px steps (the snapped delta), never below `MIN_SOLID` on that axis (the opposite edge stays fixed; it never flips), clipped to the room, and keeps the last valid rect when the result would be identical to another solid. One undo step per drag; `hard_ledges` follows the rect exactly as it does for a move, and a ledge that stops being thin loses its mark. Model: `begin_resize(sel, handle) -> bool`, `resize_to(delta)`, ended by `end_move()`. |
| Decor | New `DecorLib` (`scripts/world/decor_lib.gd`): a const `CATALOG` of `id -> {anchor, light}` for the 46 decor sprites in `assets/sprites/` (the crystals, fungus, hanging roots, stalactites and so on); `biome_of(id)` (an id is bound to a biome by its `<biome>_` prefix when `<biome>` is in `TerrainArt.biomes()` and is not `cave`, else it is `cave`); `ids_for(biome) -> Array`; `entry(id, pos) -> Dictionary` (the data a placed piece gets: `anchor: "top"` only when the catalog says so, `light` only when it has one); `texture_box(id) -> Rect2` (the sprite's box relative to `pos`: bottom-anchored `Rect2(-w/2, -h, w, h)`, top-anchored `Rect2(-w/2, 0, w, h)`). **The 21 ids the shipped rooms use are pinned** (15 cave and 6 grotto): every shipped decor entry equals `entry(id, pos)` for its id (anchor and light). The other 25 rows (all 8 `deep_*` and 11 `flooded_*`, 5 grotto and `crystal_purple`) have no shipped instance to pin, so the catalog fixes them by one rule, and a test asserts the rule: a `<biome>_<suffix>` row takes the **anchor of the cave `<suffix>` row** and the **light of the grotto `<suffix>` row when that row is pinned, else of the cave row**; `deep_bones` (no cave counterpart) is bottom-anchored with no light; `crystal_purple` takes light `Color(0.75, 0.5, 1, 1)`. The **Decor tool** shows a palette for the current room's area; a click places a piece that **stands on the surface below the click** (`anchor` bottom: `surface_below` from one pixel above the point, the probe P2 uses so a point on a surface top is not "inside" it) or **hangs from the rock above it** (`anchor` top: new `surface_above`, the bottom edge of the first rock at or above a point one pixel below the click). A click with no rock above it (under a **top exit**, where the generated ceiling is cut) or no surface below (over a floor hole) is refused with a message. Select drags with the same rule, including the P2 fallback for a pointer that dips (retry the same x at the original height). A decor id outside the catalog is a lint finding (`decor_unknown`, thirteenth rule), and `RoomBuilder.build_decor` **skips** an id with no sprite instead of calling `get_height()` on null (a hand-edited unknown id with `anchor: "top"` otherwise crashes the editor and the game as the room is built). Decor is not constrained by `pool_clearance` or `in_rock`; `over_hole` covers it. |
| Clipboard | `RoomEditModel.clipboard` (a deep copy, a model field, so it survives room switches and the Play round trip, which carries the model). **Cmd/Ctrl+C** copies the selection; **Cmd/Ctrl+V** pastes. One element at a time; copyable: solid (with its `hard` mark), creature, feature, decor; not copyable: exit (refused with a reason). A paste lands at the copy's **original local position plus (16, 16) in the same room, and at the original position in another room**, never at the pointer (one rule), and is **not snapped** (offsets are multiples of the grid, so grid-aligned stays aligned and off-grid stays off-grid). It is validated as a placement of its kind without snapping and is refused rather than moved: a solid must be wholly inside the room and not identical to another; a creature must be in the room and not in rock; a feature uses P2's surface rule (the base y is the surface found from x); decor uses its anchor rule. A pasted feature gets a fresh generated id and, per kind: a **switch's `shortcut` is its new id** (so it opens nothing until an exit uses it, exactly as a placed one), a **tablet keeps its title, text and hint**, a **pool keeps its kit and takes the target room's `area`**. The default pool is an ordinary pool for this purpose (the copy has a new id, so it is not the default). Paste with an empty clipboard says so. The keys are ignored while typing (a field keeps its own copy and paste). |
| Exit `gate` | The exit inspector gains **Gate**: a dropdown of `none` and the kit-legal skill ids (`wall_cling` is the one shipped). It sets `gate` on both halves through the same partner-write path as `shortcut` (one `_set_exit_pair_key`, not a second pairing implementation), in one undo step, and removes it for `none`. A `gate` is a label for the validator and lint, not an obstacle in play (Ruling 4). Two changes make it safe to edit: **`WorldValidator` now requires an exit's partner to carry the same `gate` as well as the same `shortcut`** (it compares only `shortcut` today, so a pair with `gate` on one half validates clean while its ungated route differs by direction), and **`over_hole` counts a gated bottom exit** (only a `shortcut` closes a hole; `RoomBuilder.is_exit_open` reads only the shortcut), so a gate no longer silences a creature or decor piece over an open hole. Dressing over a gated hole stays allowed (C3's stone arch). |
| Tablet `hint` | The tablet inspector gains **Hint**: `none` plus `RoomLint.hintable_skill_ids()`; `none` removes the key. A stored hint that is not in the list (hand-edited data) appears as its own item so the control never shows `none` for a hint that is there; `hint_unknown` still flags it. |
| Jump ruler | A **Ruler** toggle draws, at the pointer, the base jump's reach in room pixels from `RoomLint.REACH_RISE`, `REACH_GAP` and `REACH_HOP` (the constants `ledge_reach` uses): the rise box, the gap and the hop, as outlines with their numbers, labelled "base jump (lint's heuristic)". `ledge_reach` measures the gap between ledge **edges**, a ruler measures from a **point**, so they agree on the constants and differ by up to half a ledge's width on a real ledge (Ruling 9); it models no Wall Cling, swing or dash. |

## Architecture (P3)

- **Model** (`room_edit_model.gd`): kind `decor` through every arm; `hit_all`; `surface_above`; `add_decor`; `begin_resize` / `resize_to`; `copy_selection` / `paste`; `set_area`, `clear_dressing`; the solid keys in `get_field` / `set_field` (and `gate`, `hint`); `_set_exit_pair_key` generalising `_set_exit_shortcut`; the identical-solid check in `add_solid`, resize, paste and `set_field`. The file is 894 lines and grows to roughly 1150; **no split in P3** (Ruling 11).
- **Lint** (`room_lint.gd`): the thirteenth rule `decor_unknown`; `_over_hole` skips only exits with a `shortcut` for spawns and decor (and also gated exits for dressing); its comment, which says counting a gated hole "is P3's, with the gate field", is rewritten to say it now is.
- **Validator** (`world_validator.gd`): the exit-pair check compares `gate` beside `shortcut`.
- **World data** (`decor_lib.gd`, `terrain_art.gd`, `room_builder.gd`): `DecorLib`; `TerrainArt.biomes()`; `build_decor` skips a missing sprite.
- **View** (`room_view.gd`): the Decor tool; the handle drawing and picking; press and release cycling bookkeeping (candidates, travel); the ruler overlay; a selection outline for decor.
- **Panels** (`editor_panels.gd`): tool Decor in row one (Select, Solid, Creature, Feature, Decor, Exit) with a decor palette; `Ruler` in row two; the Area controls from `TerrainArt.biomes()`.
- **Inspector and slot** (`inspector_panel.gd`, `editor_slot.gd`, new `room_panel.gd`): a number control and a dropdown control; the per-kind field table extended with `solid`, `gate`, `hint`; `refresh()`; the slot shows the room panel when nothing is selected. `InspectorPanel._title` currently reads `features[index]` for any non-exit kind and is made kind-aware.
- **World view** (`world_view.gd`): area colours.
- **Docs and tools**: `docs/rooms.md` (the decor catalog, gates), `docs/playtest-checklist.md`, `tools/editor_shots.gd`.

## Failure modes and edge cases

- **Cycling.** With one candidate a click on the selected element keeps it selected; a click on empty space clears the selection as before; a drag, a sub-grid drag, a drag through rock and a drag back to the start never cycle (pointer travel decides); after cycling to candidate #2 a drag moves #2 (press keeps the selection).
- **Numeric fields.** A refused combination (outside the room, identical to another solid) reverts the control and reports the reason; typing the stored value pushes no step (`_push` declines an unchanged room); `hard` on a thick solid is refused; a solid whose `h` is typed past 24 loses its mark in the same step; after a drag or resize the field shows the new number (`refresh()`); a focused field is never overwritten while the author types in it.
- **Identical solids.** `hard_ledges` follows a rect by value, so two identical solids would make the mark ambiguous. Placement (`add_solid`), resize, paste and a typed set refuse a result identical to another solid ("an identical solid is already there"); hand-edited duplicates already in data behave as they do today.
- **Resize.** A handle dragged past the opposite side clamps at `MIN_SOLID`, never flips; a resize that would leave the room is clipped; resizing a hard ledge to thick drops its mark in the same step; a resize that makes a solid overlap a creature, feature or exit is allowed (lint reports `in_rock` / `exit_blocked`), as a drag of a solid already is; at 6x6 fit zoom (0.1229) `r` shrinks with the solid, so a small solid offers no handle it cannot also be moved from.
- **Decor.** A hanging piece under a top exit has no rock above and is refused; a standing piece over a floor hole is refused and `over_hole` covers what a hand edit makes; changing a room's area never rewrites decor; a decor piece of another biome in a room is the author's choice (Ruling 5); an id outside the catalog is lint's `decor_unknown` and is skipped by the builder, never a crash.
- **Clipboard.** Pasting with an empty clipboard says so; a paste that does not fit (solid partly outside the room) is refused, not clipped; the clipboard survives a room switch and a Play round trip; pasting a feature across rooms gives it a fresh id even when the source id is free; a cut is not offered (P4).
- **Gate.** Setting a gate writes both halves in one step; undo restores both; a gate on an exit whose partner is missing sets the one half the exit has (the validator's "no matching exit" already reports the pair); `none` removes it from both.
- **Area change.** Pools' `area` follows the room; a room with dressing moved to a biome without a piece library is validator-red until Clear dressing; Undo restores area, pools and dressing together.
- **Panels and focus.** Number controls are `SpinBox`es whose inner `LineEdit` commits on focus loss, so the P2 `_commit_pending` rule covers them; dropdowns, checkboxes and palettes are `FOCUS_NONE`; Tab, Delete, Backspace and the clipboard keys are ignored while typing (Cmd/Ctrl+S still saves).
- **Slot modes.** Three, with a fixed precedence: an open problems list wins; else the inspector for a solid, exit or feature; else the room panel. (The Kit panel that would have been a fourth is P4.)
- **Opening room.** The editor still opens on `C1` (`room_editor.gd`); with no room deletion in P3 that cannot dangle. P4's delete room makes the opening room the start room, with a first-id fallback.

## Rulings I made

1. **Dressing is not edited in P3.** The shipped game builds rooms with `RoomBuilder.simple_layers := true`, which skips the parallax stack and `SetDressing` entirely: the roughly 110 dressing entries in the data are not drawn in play today. A tool to place scenery nobody can see would edit data with no effect, and the editor's own view would need a second, fake parallax to show it. The one remedy that is needed (a room moved to a biome with no piece library goes validator-red) is the Room panel's **Clear dressing** button. Dressing waits for `simple_layers` going off (P4). Cost if wrong: Sean edits dressing by hand until then.
2. **The first draft's second half is P4.** The Start tool, shrinking and deleting rooms, the free-form Play kit, pool affinity, numeric fields for creatures, features, decor and exits, cut and duplicate, the collision view and the JSON export are not needed to author a `deep` or `flooded` room, and they carry the riskiest bookkeeping: moving the world start must move the default pool and spans three rooms in one undo; deleting a room reverses P1's "a room that was on disk is never deleted" and needs a second file-removal set, partner-exit surgery and a rule for redo, recreation of an id and undo after Save; the Kit panel reverses P2's Ruling 10 (two toggles and a constant kit) with no new fact; pool affinity's eligibility rule is **not** the validator's (it lives only in `test_rebirth_kit.gd`), so editing it would make Validate lie about the suite. Play from here already starts anywhere, so the start can wait. Cost if wrong: Sean edits `start` in a `.tres`, deletes a room file by hand, or edits a kit by text until P4; none blocks authoring a new-biome room. This is a deliberate cut of three of the first draft's success abilities (the start, delete, a free-form kit).
3. **Typed numbers and pasted elements are not snapped.** The grid is for drags; the point of a typed number is the case the grid cannot express (a ledge at y 266). Paste adds a grid-multiple offset to the original coordinates, so alignment is preserved either way. Cost if wrong: an off-grid value the next drag snaps.
4. **`gate` stays a label, and a gated bottom exit now counts as a hole.** A closed door that opens with Wall Cling is gameplay and belongs with P4's reachability; but because only a `shortcut` closes a hole in play, letting a gate silence `over_hole` would make a one-click edit hide a real defect. So `over_hole` counts gated holes for spawns and decor (dressing keeps the skip: C3's stone arch), and the validator now requires matching gates on a pair. Cost if wrong: if shipped data had a creature over a gated hole the aggregate test would say so; the plan checks that before committing.
5. **No biome-match lint for decor.** Cave decor in a `deep` room is a design choice (a shared prop). Only an id outside the catalog is a finding. Cost if wrong: an unintended mixed-biome room passes Validate.
6. **Identical solids are refused where P3 creates them.** `hard_ledges` is a list of rect values; two equal rects make a mark ambiguous (found in review: the existing move and delete use `find`). Refusing the creation is cheaper than tracking marks by index. Cost if wrong: a rare, harmless refusal when an author stacks two identical ledges.
7. **One element, copy and paste only, no pointer.** Cut and duplicate are a delete and a paste at an offset; a group move is P4's prefab stamp; a paste at the pointer would need a second placement rule for a feature already placed by surface. Cost if wrong: two extra keystrokes.
8. **Cycling is decided by pointer travel and the press keeps a selected candidate.** The model's `serial` does not advance for several ways a drag can end unchanged, and a press that re-ran `hit` would always select the first candidate, so the cycled one could never be dragged. Cost if wrong: a click that moved 2 pixels still cycles.
9. **The ruler is lint's heuristic from a point.** The constants are single-sourced so the overlay and the rule cannot disagree about them; the difference between a point and a ledge edge is stated on the overlay. Cost if wrong: a Wall Cling room looks unreachable under the ruler.
10. **A pool's `area` follows its room's on an area change.** `add_feature` stamps it from the room and both shipped pools equal their room's area, so the pool Area dropdown the first draft had would only repair a mismatch the Room panel's Area dropdown creates. Cost if wrong: an author who wants a Grotto pool in a `deep` room edits the `.tres`.
11. **No `room_edit_ops.gd` split.** The first draft's split reached into the model's private members and, with the lifecycle work gone, would hold about 80 lines of clipboard. The model grows to roughly 1150 lines; if it hurts, P4 splits by state along the field layer (`get_field` / `set_field`, already tested on its own). Cost if wrong: one large file for a phase.
12. **The decor catalog fixes the unpinned rows by a stated rule**, not by taste (Decor row), so a later change to a `deep_` or `flooded_` row is a test change that says why. Cost if wrong: a light colour or anchor the biome work adjusts.

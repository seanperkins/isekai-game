# Room Editor, Phase 3 — Design

Status: revised after round 2 of the debate (2026-10-01). Phase 3 of `docs/superpowers/specs/2026-09-29-room-editor-design.md`,
after P2 (`2026-09-30-room-editor-p2-design.md`, shipped). Sean's queue is: finish the editor, then add biomes and enemies from
*So I'm a Spider, So What?* and *That Time I Got Reincarnated as a Slime*. The art for two new biomes (`deep`, `flooded`:
terrain, back walls, parallax layers, decor sprites) is already in `assets/`, but no room uses them and the editor cannot make
one: its area list is the constant `["cave", "grotto"]` and it has no way to place decor. Round 1 found the first draft was two
phases in one; round 2 cut it again to the slice a new-biome room needs. P3 is that slice plus the cheap ergonomics authoring
needs; the rest is P4 (Ruling 2). Research: `docs/research/level-design-reference.md`.

## What I understood

After P2 Sean can build a room's solids, creatures, exits, features and kits without a text editor. He cannot yet: choose a new
room's biome from what the art supports; place the decor that makes a room read as its biome (crystals, fungus, hanging roots,
stalactites); fix a ledge to an exact number or turn a thin ledge into one you cannot jump up through; copy a ledge or a creature
from another room; pick the right one of two overlapping things; set an exit's `gate` or a tablet's `hint`; or see the jump
budget he is building to.

**Success for P3:** author a complete room in a *new biome* without a text editor: start a room in `deep` or `flooded`, draw it,
place its ledges exactly, dress it with that biome's decor (standing and hanging), copy a ledge or a creature from another room,
set its exits' gates and a tablet's hint, and see the base jump's reach while building. "Validate clean" stays the same thing as
"the suite's rule tests would pass", for decor and for gates as well.

## The phases

| Phase | What it delivers |
|---|---|
| P1 (shipped) | Separate editor scene; Solids, creatures, paired exits, New room beside, undo, Validate, save, Play from here |
| P2 (shipped) | `RoomLint`, the live problems list, features (pool, tablet, switch, rebirth pool), the inspector (exit shortcut, tablet text, switch, pool kit), Grow, two Play toggles, the World view |
| **P3 (this spec)** | Biomes from data for New room; selection cycling; solid numeric fields and the hard-ledge toggle; the Decor tool; copy and paste of a ledge or a creature; exit `gate` and tablet `hint`; a jump ruler |
| P4 (later spec) | The Room panel (change a room's area, clear its dressing, delete, shrink); resize handles; the Start tool and moving the world's start with its default pool; a free-form Play kit; pool affinity (with its eligibility rule moved into lint); numeric fields for creatures, features, decor and exits; copying features and decor; cut and duplicate; a collision-only view; a JSON lint export for CI; physical reachability, assumed abilities and gate enforcement; prefab stamps and room templates; moving a room on the World view; dressing; autosave |

## Decisions (P3)

| Area | Decision |
|---|---|
| Biomes | The area list comes from data, not a constant: `TerrainArt.biomes() -> Array` returns the sorted directory names under `res://assets/tiles/` that `has_biome` accepts (today `cave`, `deep`, `flooded`, `grotto`). New Room's Area control reads it (`EditorPanels.AREAS` is a `const` today and becomes a function; its four uses change), and `new_room_beside` already refuses an area without art. The World view colours a room by its area: `AREA_FILL` gains explicit `deep` and `flooded` entries and any other area keeps `FILL_UNKNOWN`. A new biome's *art* needs no code change to be offered for a new room; its *decor* needs `DecorLib.CATALOG` rows. Changing an existing room's area is P4's Room panel (Ruling 2). |
| Selection kinds | One new kind beside `solid`, `spawn`, `exit`, `feature`: **`decor`**. `hit` priority: spawn, feature, decor, exit, solid. Every kind has an explicit arm in `hit`, `begin_move`, `move_to`, `delete_selection`, the outline and the inspector, and each `_` arm refuses (the rule P2 set). The slot (P2's two modes, the problems list or the inspector, otherwise hidden) now shows an inspector for a **solid** as well as an exit or a feature; a creature or a decor piece selects with the slot hidden. |
| Selection cycling | The model gains `hit_all(room_id, p, pick) -> Array` (every element under the point in the priority order above, nearest spawn first, smaller solids first); `hit` is its first element. The view keeps `_cycle = {point, list}` (the screen point and candidate list of the press that made the current selection). **At press:** compute `cands = hit_all`; if the current selection is in `cands`, `cands` equals `_cycle.list` and the press is within 4 screen px of `_cycle.point` (the same spot, clicked again), **keep** the selection and remember that the press may cycle; otherwise select `cands[0]` as P2 does and set `_cycle` to this press. A press on a creature that stands beside a selected ledge therefore selects the creature (its candidate list differs), and a second press at the same spot keeps the selection so a cycled-to element can be dragged. **Drags start only after the pointer has travelled 3 screen px (`CLICK_PX`) from the press**; until then no `move_to` happens, and then the move is applied from the original press point (so there is no lag and no nudge from jitter). **At release**, if no drag started, the press may cycle and there is more than one candidate, the selection moves to the next candidate after the current one (wrapping), `_cycle.point` becomes this press and `selection_changed` is emitted. It is decided by pointer travel, not by the model's `serial` (which does not advance for a drag that ends where it began, a sub-grid drag or a creature dragged through rock). |
| Solid numeric fields | A selected solid gets a panel with `x`, `y`, `w`, `h` and **Rock from below** (below). Each number is a `SpinBox` (whole pixels, `min_value` / `max_value` from the room: `x` 0..width-`MIN_SOLID`, `y` 0..height-`MIN_SOLID`, `w` `MIN_SOLID`..width, `h` `MIN_SOLID`..height, so the control clamps what it cannot hold) that commits on `value_changed` (Enter, an arrow or focus loss; `_commit_pending` releases focus first, so the P2 rule covers it). The model keys are `get_field` / `set_field` `x`, `y`, `w`, `h`, `hard`. A set builds the new rect exactly (**not snapped**: typed numbers exist for what the grid cannot express, such as C1's ledge at y 266) and goes through the solid chokepoint below, which refuses a rect that is not wholly inside the room or is identical to another solid; the control then shows the stored value again and the reason goes to the status bar. |
| The solid chokepoint | Every path that changes a solid's rect (a drag, a typed set, and the toggle) calls one writer, `_put_solid(room_id, i, rect, marked) -> String`: it refuses a rect smaller than `MIN_SOLID`, not wholly inside the room, or **identical to another solid** (`hard_ledges` holds rect *values*, so two equal rects make a mark ambiguous: dragging an unmarked ledge onto an identical marked one would otherwise move the mark onto the wrong rect); it writes the rect; and it keeps `hard_ledges` in step (`marked` and thin: the rect is in the list; otherwise it is not). A drag passes the mark it captured at `begin_move` (`marked = original mark and the rect is thin`, so a drag that goes thick and back to thin keeps its mark); a refused drag step keeps the last valid rect, as the creature arm does. `add_solid` and a paste refuse an identical rect with the same one-line test (`_has_solid`). |
| Hard ledges | A solid that is thin (`size.y <= 24` and `size.x > 24`: `RoomBuilder.is_one_way` without the mark) has a **Rock from below** checkbox, the `hard` field: it adds or removes the rect in `hard_ledges` (`set_field(hard, true)` on a thick solid is refused). A solid that stops being thin loses its mark through the chokepoint. The Solid tool's live label reads the mark. |
| Stale numbers | The inspector is still rebuilt only when the selection changes. `InspectorPanel.refresh()` (a loop over the existing controls using the existing `_show_stored`) re-reads every control on every `_sync` while the same selection is open, **skipping a control that has keyboard focus** (a `SpinBox`'s inner `LineEdit` included): it **re-derives each number's `min_value` / `max_value` from the room** (a Grow changes the room's size under a selected solid), writes with `set_value_no_signal` (so a refresh can never commit), and shows or hides the **Rock from below** checkbox as the solid is thin or not. Without it a number typed before a drag would still show the old value and a focus-out would commit it, moving the element back. The string dropdowns (gate, hint) are one generic string-choice control, of which the level choice is a case. |
| Decor | New `DecorLib` (`scripts/world/decor_lib.gd`): a literal `CATALOG` of `id -> {anchor, light}` for the 46 decor sprites in `assets/sprites/` (the crystals, fungus, hanging roots, stalactites and so on), `biome_of(id)` (an id is bound to a biome by its `<biome>_` prefix when `<biome>` is in `TerrainArt.biomes()` and is not `cave`, else it is `cave`; `tools/prefabs.gd`'s `decor_id(id, biome)` is the forward mapping and a test pins that the two agree), `ids_for_biome(biome) -> Array`, `entry(id, pos) -> Dictionary` (the data a placed piece gets: `anchor: "top"` only when the catalog says so, `light` only when it has one) and `texture_box(id) -> Rect2` (bottom-anchored `Rect2(-w/2, -h, w, h)`, top-anchored `Rect2(-w/2, 0, w, h)`). **The 21 ids the shipped rooms use are pinned**: every shipped decor entry equals `entry(id, pos)` for its id (15 cave and 6 grotto ids, each with one consistent anchor and light). The other 25 rows (all 8 `deep_*` and 11 `flooded_*`, 5 grotto and `crystal_purple`) have no shipped instance and are **chosen, not pinned**: each takes the anchor of its cave counterpart and the light of its grotto or cave counterpart, a convention a later biome pass is free to retune by editing the catalog. The **Decor tool** shows a palette for the current room's area (rebuilt on `open_room`; `_free_rect` counts it like the other palettes); a click places a piece that **stands on the surface below the click** (`anchor` bottom: `surface_below` from one pixel above the point, the probe P2 uses so a point on a surface top is not "inside" it) or **hangs from the rock above it** (`anchor` top: new `surface_above`, the bottom edge of the first rock at or above a point one pixel below the click; a closed shortcut gate is not rock, as for `surface_below`'s default). A click with no rock above it (under a **top exit**, where the generated ceiling is cut) or no surface below (over a floor hole) is refused with a message. Select drags with the same rule, including the P2 fallback for a pointer that dips (retry the same x at the original height). A decor id outside the catalog is a lint finding (`decor_unknown`, thirteenth rule; its pick, and the decor `over_hole` finding's, is `{kind: "decor", index}`), and `RoomBuilder.build_decor` **skips** an id with no sprite instead of calling `get_height()` on null (a hand-edited unknown id with `anchor: "top"` otherwise crashes the editor and the game as the room is built). Decor is not constrained by `pool_clearance` or `in_rock`; `over_hole` covers it. |
| Clipboard | `RoomEditModel.clipboard` (a deep copy, a model field, so it survives room switches and the Play round trip, which carries the model) plus a paste counter. **Cmd/Ctrl+C** copies the selection and resets the counter; **Cmd/Ctrl+V** pastes. Copyable: a **solid** (with its `hard` mark) and a **creature**; anything else is refused with "only a ledge or a creature can be copied" (features and decor have palettes; P4 widens the clipboard). The n-th paste since the copy lands at the **original local position plus (16 n, 0)**, in any room (never at the pointer, never moved down: floor-standing content would sink into the floor), and is **not snapped** (the offset is a grid multiple, so alignment is preserved either way). It is validated and **refused rather than moved**: a solid must be wholly inside the room and not identical to another solid (through `_has_solid`); a creature must be inside the room and not in rock, placed by a `_put_spawn(room, id, pos)` that `add_spawn` also uses after snapping. A paste selects the new element, as every `add_*` does. Empty clipboard says so. The keys are ignored while typing (a field keeps its own copy and paste) and while the World view is open. |
| Exit `gate` | The exit inspector gains **Gate**: a dropdown of `none` and `RoomLint.GATES` (a one-entry constant, `["wall_cling"]`, until P4 gives gates teeth; a stored gate outside it appears as its own item so the control never lies). It sets `gate` on both halves through the same partner-write path as `shortcut` (`_set_exit_shortcut` becomes one `_set_exit_pair_key`, not a second pairing implementation), in one undo step, and removes it for `none`. A `gate` is a label for the validator and lint, not an obstacle in play (Ruling 4). Two changes make it safe to edit: **`WorldValidator` now requires an exit's partner to carry the same `gate` as well as the same `shortcut`** (it compares only `shortcut` today, so a pair with `gate` on one half validates clean while its ungated route differs by direction; shipped pairs C2/C3 and G3/G5 match), and **`over_hole` counts a gated bottom exit for spawns and decor** (only a `shortcut` closes a hole; `RoomBuilder.is_exit_open` reads only the shortcut), so a gate no longer silences a creature or a decor piece over an open hole. Dressing over a gated hole stays allowed (C3's stone arch); C3's gated hole has nothing else over it, so shipped data stays clean. |
| Tablet `hint` | The tablet inspector gains **Hint**: `none` plus `RoomLint.hintable_skill_ids()`; `none` removes the key. A stored hint that is not in the list appears as its own item; `hint_unknown` still flags it. |
| Jump ruler | A **Ruler** toggle draws, at the pointer, the base jump's reach in room pixels from `RoomLint.REACH_RISE`, `REACH_GAP` and `REACH_HOP` (the constants `ledge_reach` uses): the rise box, the gap and the hop, as outlines with their numbers, labelled "base jump (lint's heuristic)". `ledge_reach` measures the gap between ledge **edges**, a ruler measures from a **point**, so they agree on the constants and differ by up to half a ledge's width on a real ledge (Ruling 9); it models no Wall Cling, swing or dash. |

## Architecture (P3)

- **Model** (`room_edit_model.gd`): kind `decor` through every arm; `hit_all`; `surface_above`; `add_decor`; `_put_solid` and `_has_solid`; `_put_spawn`; `copy_selection` / `paste`; the solid keys in `get_field` / `set_field` (and `gate`, `hint`); `_set_exit_pair_key` generalising `_set_exit_shortcut`; the move arm and the decor arms use the chokepoint and the P2 dip fallback. The file is 894 lines and grows to roughly 1050; **no split in P3** (Ruling 11).
- **Lint** (`room_lint.gd`): the thirteenth rule `decor_unknown`; `GATES`; `_over_hole` skips only exits with a `shortcut` for spawns and decor (and also gated exits for dressing); its comment, which says counting a gated hole "is P3's, with the gate field", is rewritten; the pick-kinds header doc gains `decor`.
- **Validator** (`world_validator.gd`): the exit-pair check compares `gate` beside `shortcut`; the class doc gains it.
- **World data** (`decor_lib.gd`, `terrain_art.gd`, `room_builder.gd`): `DecorLib`; `TerrainArt.biomes()`; `build_decor` skips a missing sprite.
- **View** (`room_view.gd`): the Decor tool; the cycling and drag-threshold bookkeeping in `_press` / `_motion` / `_release`; the ruler overlay; a selection outline for decor.
- **Panels** (`editor_panels.gd`): tool Decor in row one (Select, Solid, Creature, Feature, Decor, Exit) with a decor palette (`FOCUS_NONE`); `Ruler` in row two; `areas()` from `TerrainArt.biomes()`.
- **Inspector and slot** (`inspector_panel.gd`, `editor_slot.gd`): a number control and a string-choice control; the per-kind field table extended with `solid`, `gate`, `hint`; `refresh()`; `_title` made kind-aware (it reads `features[index]` for any non-exit kind today); `RoomEditor._inspectable` gains `solid`.
- **World view** (`world_view.gd`): two `AREA_FILL` entries.
- **Docs and tools**: `docs/rooms.md` (the decor catalog, gates), `docs/playtest-checklist.md`, `tools/editor_shots.gd`.

## Failure modes and edge cases

- **Cycling.** With one candidate a click on the selected element keeps it selected; a click on empty space clears the selection as before; a press on a different element (or at a different spot) selects that element's top candidate; with three candidates repeated clicks at one spot walk through all three and wrap; after cycling to candidate #2 a drag moves #2; a press-and-release with up to 2 screen pixels of jitter never moves anything and may cycle; the same jitter at 6x6 fit zoom (0.1229, where one screen pixel is 8.1 room pixels) moves nothing because no drag starts below 3 px.
- **Numeric fields.** A refused combination (outside the room, identical to another solid) reverts the control and reports the reason; typing the stored value pushes no step (`_push` declines an unchanged room); `hard` on a thick solid is refused; a solid whose `h` is typed past 24 loses its mark in the same step and its checkbox hides; after a drag the field shows the new number; after a Grow the ranges follow the new room size and the shifted value is shown, not clamped; a focused field is never overwritten while the author types in it.
- **Identical solids.** Placement, a drag step, a typed set and a paste refuse a result identical to another solid ("an identical solid is already there"); a refused drag step keeps the last valid rect; hand-edited duplicates already in data behave as they do today.
- **Decor.** A hanging piece under a top exit has no rock above and is refused; a hanging piece does not hang from a closed shortcut gate; a standing piece over a floor hole is refused and `over_hole` covers what a hand edit makes; a decor piece of another biome in a room is the author's choice (Ruling 5); an id outside the catalog is lint's `decor_unknown` and is skipped by the builder, never a crash.
- **Clipboard.** Pasting with an empty clipboard says so; a paste that does not fit (a solid partly outside the room, a creature in rock) is refused, not moved; a second paste lands 16 px further right, so it is never an identical solid; the clipboard survives a room switch and a Play round trip; a feature, decor piece or exit is refused with a reason.
- **Gate.** Setting a gate writes both halves in one step; undo restores both; a gate on an exit whose partner is missing sets the one half the exit has (the validator's "no matching exit" already reports the pair); `none` removes it from both.
- **Panels and focus.** Number controls are `SpinBox`es whose inner `LineEdit` commits on focus loss, so the P2 `_commit_pending` rule covers them; dropdowns, checkboxes and palettes are `FOCUS_NONE`; Tab, Delete, Backspace and the clipboard keys are ignored while typing (Cmd/Ctrl+S still saves).
- **Slot modes.** Two, with P2's precedence: an open problems list wins; else the inspector for a solid, exit or feature; else hidden. A creature or a decor piece selected hides the slot.

## Rulings I made

1. **Dressing is not edited in P3, and there is no Clear dressing.** The shipped game builds rooms with `RoomBuilder.simple_layers := true`, which skips the parallax stack and `SetDressing` entirely: the roughly 110 dressing entries in the data are not drawn in play today. A tool to place scenery nobody can see would edit data with no effect. Cost if wrong: Sean edits dressing by hand until P4.
2. **The first draft's second half, the Room panel and resize handles are P4.** The Start tool, shrinking and deleting rooms, the free-form Play kit, pool affinity, numeric fields for creatures, features, decor and exits, copying features and decor, cut and duplicate, the collision view and the JSON export are not needed to author a `deep` or `flooded` room and carry the riskiest bookkeeping: moving the world start must move the default pool and spans three rooms in one undo; deleting a room reverses P1's "a room that was on disk is never deleted" and needs a second file-removal set and rules for redo, recreating an id and undo after Save; the Kit panel reverses P2's Ruling 10 with no new fact; pool affinity's eligibility rule is **not** the validator's (it lives only in `test_rebirth_kit.gd`), so editing it would make Validate lie about the suite. Round 2 added: **changing an existing room's area** (the Room panel) is not needed because `new_room_beside` already takes an area, and it forces a pool-area rewrite, a third slot mode and a **Clear dressing** button that is a data-loss control on every shipped room, all to repair a state the panel itself creates; and **resize handles** duplicate the exact resize the numeric fields give (the Solid tool gives the rough one) while carrying the most view state (handle picking, cycle interplay, a 6x6 zoom where `r` falls to a pixel). Cost if wrong: Sean edits `area` or `start` in a `.tres`, deletes a room file, edits a kit by text, or redraws a ledge to resize it, until P4; none blocks authoring a new-biome room.
3. **Typed numbers and pasted elements are not snapped.** The grid is for drags; the point of a typed number is the case the grid cannot express (a ledge at y 266). A paste adds a grid-multiple offset to the original coordinates, so alignment is preserved either way. Cost if wrong: an off-grid value the next drag snaps.
4. **`gate` stays a label, and a gated bottom exit now counts as a hole.** A closed door that opens with Wall Cling is gameplay and belongs with P4's reachability; but because only a `shortcut` closes a hole in play, letting a gate silence `over_hole` would make a one-click edit hide a real defect. So `over_hole` counts gated holes for spawns and decor (dressing keeps the skip: C3's stone arch), and the validator now requires matching gates on a pair. Checked against the shipped data: the only gated bottom exit is C3's, nothing of C3's spawns or decor is over it, and both shipped gate pairs match. Cost if wrong: a creature the author puts over a gated hole is flagged.
5. **No biome-match lint for decor.** Cave decor in a `deep` room is a design choice (a shared prop), and the catalog allows any id in any room through the palette's own biome filter being a convenience, not a rule. Only an id outside the catalog is a finding. Cost if wrong: an unintended mixed-biome room passes Validate.
6. **One chokepoint refuses identical solids.** `hard_ledges` is a list of rect values; two equal rects make a mark ambiguous (found in review: the existing move and delete use `find`, and a drag onto an identical marked ledge would steal its mark). Refusing the creation at `_put_solid` / `_has_solid` is cheaper than tracking marks by index and also stops every other path. Cost if wrong: a rare, harmless refusal when an author stacks two identical ledges.
7. **The clipboard copies a ledge or a creature only, by copy and paste only.** That is what "copy a ledge or a creature from another room" asks; features and decor have palettes; cut and duplicate are a delete and a paste at an offset; a group move is P4's prefab stamp. Paste lands at the original position plus (16 n, 0) with no second rule for the pointer or for surface-standing kinds (a down-right offset sinks every floor creature and feature into the floor: 15 of 50 shipped creatures and all 7 shipped features stand on the floor line). Cost if wrong: re-placing a feature or decor piece from its palette.
8. **Cycling is a repeated click at one spot, decided by pointer travel, with drags deferred by 3 px.** Keeping the selection on any press that lands on it would make a creature beside a selected ledge undraggable; deciding by the model's `serial` misfires when a drag ends unchanged; and a drag that starts on the first motion event turns a 1 px click jitter at 6x6 zoom into an 8 px nudge. Cost if wrong: a drag shorter than 3 screen px does nothing.
9. **The ruler is lint's heuristic from a point.** The constants are single-sourced so the overlay and the rule cannot disagree about them; the difference between a point and a ledge edge is stated on the overlay. It is the cheapest item to drop if the phase runs long. Cost if wrong: a Wall Cling room looks unreachable under the ruler.
10. **The unpinned decor rows are chosen, not pinned.** The 25 rows with no shipped instance follow the stated convention (cave anchor, grotto or cave light) and are literal table rows; a test pins only what the data pins (the 21 ids), that every row has a sprite and that the fields have the right type. The biome work is free to retune the rest by editing the catalog. Cost if wrong: a light colour or an anchor the biome work adjusts.
11. **No `room_edit_ops.gd` split.** The first draft's split reached into the model's private members and, with the lifecycle work gone, would hold little. The model grows to roughly 1050 lines; if it hurts, P4 splits by state along the field layer (`get_field` / `set_field`, already tested on its own). Cost if wrong: one large file for a phase.
12. **The World view gets two explicit colours, not a derived one.** A new biome already means a deliberate edit to `TerrainArt`'s tables; `FILL_UNKNOWN` answers any other area. Cost if wrong: a new biome is grey on the overview until it gets an entry.
13. **The Gate dropdown offers one entry.** `wall_cling` is the only movement skill any shipped gate means; offering every kit-legal skill would offer 15 labels that nothing reads. P4 widens `RoomLint.GATES` when gates get teeth. Cost if wrong: a gate on another skill is typed in a `.tres`.

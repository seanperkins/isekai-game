# Areas, part one: the builder and the forest (F2a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use ml:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A headless tool writes rooms from area modules, checks the whole world before it writes, and attaches them to the shipped world; the forest (nine rooms) is the first area built with it.

**Architecture:** `AreaKit` (static helpers: `room`, `ledge`, `stairs`, `link`, `spawn`, `decor`, `feature`) builds `RoomDef`s. An area module (`tools/areas/<area>.gd`, extends `AreaModule`) adds its rooms to a world dictionary and attaches them to shipped rooms. `AreaBuilder` loads the shipped rooms, runs the modules, runs `WorldValidator` and `RoomLint`, and serializes each changed room with `ResourceSaver`, with the script's random ext-resource id pinned so a re-run changes nothing. `tools/build_areas.sh` is the command.

**Tech Stack:** Godot 4.7 GDScript (headless, `godot --headless -s`), GUT (`tools/run_tests.sh [filter]`).

**Spec:** `docs/research/areas-f2.md`, `docs/research/area-level-design.md` (sections 6 and 17).

## Global Constraints

- The builder never writes a world that has a `WorldValidator` error or a `RoomLint` finding; it prints them and exits non-zero.
- A re-run with nothing changed writes nothing (the checked-in files equal what the builder would write).
- Shipped rooms change only by the exits the modules attach; their hand-authored solids, spawns, decor and features are untouched.
- Forest spawns are shipped creatures and support monsters that name the forest in the design table; twins are placed in F2f.
- No altars in the forest (pools only). No push. No attribution lines in commits. No time or effort estimates.

## Review Focus

- A re-run of the builder changes no file, and the written rooms load back as the same `RoomDef`.
- Every forest exit has a partner on the opposite edge with the same world span (the validator's rule), and the new rooms do not overlap a shipped one.
- A forest room that the lint cannot reach, or a spawn that cannot stand where it is put, fails the build rather than shipping.
- The attached shipped rooms (C3, C6) still pass every existing room test.
- The forest is reachable from the start room and the cave is still reachable without the forest.

### Task 1: The area kit

**Files:**
- Create: `tools/areas/area_kit.gd`, `tools/areas/area_module.gd`
- Test: `tests/test_area_kit.gd`

**Interfaces:**
- Produces: `class_name AreaKit` with `static room(id: String, area: String, cell: Vector2i, size := Vector2i.ONE) -> RoomDef`; `floor_y(r: RoomDef) -> float` (room height less `RoomDef.FLOOR`); `stand(surface_y: float) -> float` (a creature's spawn y: the surface less `Enemy.BODY_BOTTOM`); `ledge(r, x: float, y: float, w: float) -> Rect2` (a 12 px ledge whose top is `y`, appended to `r.solids`); `stairs(r, x: float, y: float, dx: float, rise: float, count: int, w: float) -> Array` (`count` ledges, each `rise` higher and `dx` further, the first with its top at `y`; refuses a rise above `RoomLint.REACH_RISE`); `start(r, x: float)` (sets `r.start` on the floor stand); `spawn(r, creature_id: String, x: float, surface_y: float)`; `decor(r, id: String, x: float, surface_y: float, extra := {})`; `feature(r, kind: String, id: String, x: float, surface_y: float, extra := {})`; `link(a: RoomDef, b: RoomDef, edge: String, from_world: float, to_world: float, extra := {}) -> bool` (adds the exit to `a` on `edge` and its partner to `b` on the opposite edge, spans converted to each room's own pixels; false, and nothing added, when the two rooms do not touch along that edge or the span leaves either edge's range). `class_name AreaModule` (RefCounted) with `func area() -> String` and `func build(world: Dictionary) -> void` (world: room id -> RoomDef, the shipped rooms included).
